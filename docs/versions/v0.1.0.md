# Auditoria técnica — v0.1.0

## Objetivo

Estabelecer uma base executável, barata de operar e segura para evoluir o domínio de
aluguel de ferramentas. Esta versão não pretende realizar uma locação completa.

## Entregas

- usuário Django customizado desde a primeira migration;
- organizações e vínculos com três papéis iniciais;
- matriz e filiais com CNPJ numérico e alfanumérico;
- categorias, modelos e ativos físicos;
- validação de relações dentro da mesma organização;
- valor diário e caução não negativos;
- estabelecimento obrigatório em toda unidade física;
- Admin para inspeção e cadastro inicial;
- ambientes separados de desenvolvimento, teste e produção;
- Docker Compose com PostgreSQL e healthchecks;
- CI com PostgreSQL;
- documentação técnica e contexto para IA.

## Migrations

| Módulo | Migration | Efeito |
|---|---|---|
| `accounts` | `0001` | cria usuário customizado |
| `organizations` | `0001` | cria organização e membership |
| `catalog` | `0001` | cria categoria, modelo e unidade |
| `organizations` | `0002` | cria estabelecimento e regras de CNPJ |
| `catalog` | `0002` | relaciona unidade/estabelecimento e protege valores |
| `catalog` | `0003` | preenche vínculos antigos e torna estabelecimento obrigatório |

`catalog.0003` é uma data migration. Para cada organização com unidades sem
estabelecimento, escolhe a matriz ativa; na ausência dela, escolhe o primeiro
estabelecimento; se nenhum existir, cria `Matriz`. Só depois altera a coluna para
`NOT NULL`.

## Verificação da versão

Critérios locais:

- `ruff check .`;
- `makemigrations --check --dry-run`;
- `manage.py check`;
- `manage.py check --deploy` com configurações de produção;
- migrations em base limpa e em base v0.1 anterior;
- suíte `pytest`;
- inspeção do diff para segredos e artefatos locais.

O resultado exato da execução é registrado na descrição do commit ou pull request de
fechamento para não deixar números voláteis dentro deste documento.

## Limitações conhecidas

| Área | Limitação | Correção candidata |
|---|---|---|
| Autorização | Admin não filtra dados pelo membership | serviço de tenant e querysets escopados |
| Papéis | enum existe sem matriz de permissões | política por caso de uso e testes |
| Estado do ativo | qualquer transição válida na enum é aceita | máquina de estados transacional |
| Preço | somente `daily_rate` no modelo | política versionada hora/dia/mês |
| Auditoria | timestamps não dizem quem alterou | eventos/audit log para ações críticas |
| Arquivos | sem armazenamento persistente de mídia | object storage quando fotos/documentos entrarem |
| Backup | não automatizado pelo código | política gerenciada e teste de restauração |
| API | ainda inexistente | API por casos de uso, depois de clientes e preços |
| Observabilidade | somente healthchecks | logs estruturados, erros e métricas |
| Depreciação | não modelada | dados patrimoniais, método, vida útil e eventos |

## Decisão de encerramento

A fundação estará pronta para publicação quando todas as verificações passarem e a CI
do pull request confirmar PostgreSQL. Funcionalidades de cliente e locação pertencem a
versões seguintes para manter migrations e revisões pequenas.
